# Worktree Ownership

worktree 按垂直功能切片登记，而不是按单一目录硬隔离。一个功能可以同时拥有领域实现、世界适配、表现层窗口和测试；所有列出的文件都必须服务于同一主功能，不得把新业务逻辑写回别的功能内部。

每个功能 worktree 在开始修改前填写以下模板。跨多个相关目录是允许的，但共享入口必须列入“潜在冲突入口”，并通过“最小适配文件”限制改动面。

```text
主功能:
可自由修改:
最小适配文件:
稳定接口:
潜在冲突入口:
验证命令:
```

填写说明：

- `主功能`：一句话说明用户可见的垂直功能。
- `可自由修改`：属于该功能的领域、世界、表现和测试目录，可跨多个相关目录。
- `最小适配文件`：必要的共享入口改动，限定为转发、信号或构造注入。
- `稳定接口`：跨模块使用的契约、结果字段、信号或构造参数。
- `潜在冲突入口`：`project.godot`、`scenes/Main.tscn`、`scripts/main.gd`、兼容门面和回归 runner 等热点文件。
- `验证命令`：解析、架构检查、功能回归和必要的运行时检查。

架构检查命令：

```powershell
.\tools\check_architecture.ps1 -Root .
```

集成 worktree 负责合并前置基础提交，并复核所有 ownership 记录和共享入口冲突。
